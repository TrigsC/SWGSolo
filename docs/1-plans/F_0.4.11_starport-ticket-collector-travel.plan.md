# Starport Ticket-Collector Travel (Pass 5) Implementation Plan — REWORKED

## Overview

The cell-navigation fixes (`F_0.4.8` enter, `F_0.4.9` egress, `F_0.4.10`
nearest-portal) let a bot walk into and out of building cells. This plan makes
**interplanetary travel realistic**: a traveling bot walks **through the starport
interior to within ~8 m of the ticket collector** (in the enclosed hangar hollow),
boards, and on arrival **walks back out of the hollow through the interior to the
outside world** — instead of teleporting from ~20 m "near" the starport.

Both directions are now **proven live** with the diagnostic harness (see Problem
Statement), so this rework specifies the exact, validated mechanics plus the six
Codex-review fixes that sent the first draft back for `NEEDS_REWORK`.

Owner decisions: target the **ticket collector in the hollow** (full realism); a bot
must **actually reach ~8 m of the collector** (board-from-near only as a bounded
unreachable fallback); keep the diagnostic in place to verify, strip + release the
whole train together at the end.

## Problem Statement

Validated facts (from the live `cellnav.log` investigation; harness archived as
`cellnav_fullroundtrip_ok.log`):

- **The ticket collector is an outdoor world object** (`isTicketCollector()`,
  `TangibleObject`) at Mos Eisley world `(3628.79, -4790.9)`, `cell 0`,
  `rootParent = 0` — sitting in the **enclosed hangar hollow** ~66 m behind the
  interior hall. It is cell-less but walled in: unreachable by naive overland
  (`moveTo` runs into the building and stalls ~48 m short; going around the
  perimeter stalls ~49 m short).
- **`findPath` routes through the portal graph only when the start OR the target is
  a cell** — never `cell 0 → cell 0`. Proven: `findPath(interior cell → hollow
  collector)` routes through (reached **1.79 m**); `findPath(hollow cell 0 → outside
  cell 0)` returns a direct 6-node overland path that hits the wall.
- **The `F_0.4.9` cell-egress logic hijacks** a naive "move to an outdoor target
  from inside a cell": it egresses out the nearest (front) portal, so a bot heading
  for the far hollow collector leaves the building and perimeter-runs instead.
- Engine primitives: `PlanetTravelPoint::isInterplanetary()` (starport vs intra-
  planet shuttleport); `TangibleObject::isTicketCollector()` (locate via
  `getInRangeObjects`, like the PvE mission-terminal scan).
- The existing miner P.4.5b travel boards from ~20 m near and teleports to the
  destination **outdoor** arrival; its `onPathFailed` boards **immediately** (no
  bounded approach). PvP has a `shuttleTargetIsCollector` notion but could only use
  outdoor collectors.

**Proven mechanics (the core of this rework):**
- **Departure (outside → collector):** `moveToInterior(interior cell)` to enter,
  then a **directed** route to the collector with the **egress suppressed**
  (`cellEgressSuppressed`) so `findPath(interior cell → hollow collector)` routes
  through the portal graph. Reached the collector at **1.79 m**.
- **Arrival (hollow → outside):** cannot `findPath` `cell0 → cell0`, so **re-enter a
  cell first** — `moveToInterior(any interior cell)` (target is a cell, so
  `findPath(hollow → cell)` re-engages the portal graph) — then `moveTo(outside)`
  with the egress **enabled**, letting the `F_0.4.9` egress leg take it out the
  front. Reached the outside at **2.84 m**.

## Solution Architecture

A shared, gated **ticket-collector travel** capability composing the validated
mechanics with the existing board/teleport:

1. **Trip-type gate** — use `PlanetTravelPoint::isInterplanetary()`: off-world trips
   use the **star port** collector flow below; intra-planet trips keep the existing
   simple shuttleport flow (unchanged).
2. **Locate the collector** — `resolveNearestTicketCollector(zone, nearWorld)`
   (already built for the diagnostic: `getInRangeObjects` filtered by
   `isTicketCollector()`, snapshots `{oid, worldPos, localPos, cell}`).
3. **Departure leg (reach the collector):**
   a. **Dismount** any vehicle *before* any interior movement (see Codex fix #3).
   b. `moveToInterior(interior entry cell)` to get inside the starport.
   c. Set `cellEgressSuppressed` and issue a **directed** move to the collector
      world position, so `findPath` routes through the interior to the hollow.
   d. **Board only when actually within `boardRadius` (~8 m) of the collector
      snapshot** (real distance + containment check, see Codex fix #2), then reuse
      the existing `boardInterplanetaryShuttle` teleport.
4. **Arrival leg (walk out of the hollow):** the board teleport places the bot at
   the destination's hollow/near-collector point; to reach the open world it
   **re-enters a cell** (`moveToInterior` a destination-starport interior cell) then
   `moveTo(outsideArrival)` with egress **enabled** → out the front.
5. **Bounded approach + fallback** — the directed collector approach is allowed a
   bounded number of attempts / a TTL (Codex fix #4); only on exhaustion (or no
   collector found) does it fall back to the current board-from-near teleport.

## Implementation Details

### 1. Two shared, production resolvers (kept, not stripped)

**File**: `SimPlayerManager.{h,cpp}`.

- **`resolveNearestTicketCollector`** (already built during investigation) — the
  board target. For the Mos Eisley hollow it returns `cell = null` (the collector is
  an outdoor `cell 0` object); that is correct for the *board* endpoint. Keep it
  (its diagnostic-only `CellNavDiagLog` line is removed at strip).
- **NEW `resolveStarportInteriorWaypoint(zone, starportNearWorld, out{worldPos,
  localPos, cell})`** — the production source for the **interior entry cell** both
  departure (enter) and arrival (re-enter) require. `resolveNearestTicketCollector`
  cannot supply it (its collector is cell-less), and the only current cell resolver
  is the diagnostic `resolveCellNavDiagnosticRoute` (removed at strip). This new
  resolver works as follows (Codex fix #11 — deterministic building selection + a
  derived interior point, since the production input may be the cell-less hollow, not
  a known interior coordinate):
  1. **Identify the starport building deterministically**: `getInRangeObjects`
     around the travel point / collector, filter `isBuildingObject()` **with a
     non-null `PortalLayout`** (a starport is a cell-bearing building), and select the
     one whose exterior footprint/bounds contain the travel point (or nearest such) —
     do **not** infer the building from the collector's parent (it is `rootParent=0`)
     or risk selecting an adjacent non-starport building.
  2. **Derive an interior point WITHOUT a hand-typed coordinate**: enumerate that
     building's cells (`getCell(1..getTotalCellNumber())`) and, for a navigable
     interior cell, take a floor point from the cell's `FloorMesh` (a floor-path node
     / triangle centroid) transformed to world via the building transform — reusing
     the proven `getCellFloorCollision`/`transformToModelSpace` machinery from the
     diagnostic's `resolveCellNavDiagnosticRoute` (which entered the hall cell live).
     It does **not** depend on `isTravelTerminal()` (which does not exist; only
     `isTerminal()`).
  3. **Validate the route**: confirm `findPath` reaches the chosen interior point
     from the current position before committing; if not, try the next cell.
  4. **Tri-state result (Codex fix #13)**: return `WAYPOINT_FOUND` (interior cell +
     point), `NO_INTERIOR` (building has no `PortalLayout`/cells — a genuinely
     outdoor starport, e.g. Dantooine), or `RESOLVE_FAILED` (transient/algorithmic
     miss). **Only `NO_INTERIOR` takes the outdoor path**; `RESOLVE_FAILED` is
     retried under the bounded approach and must never silently pick the outdoor path
     at an enclosed starport.
  This resolver is **retained** past the strip (generalize/promote the diagnostic
  cell-resolution code rather than deleting it) — it is the production interior
  waypoint for both endpoints.

### 2. Directed interior route without egress hijack (promote `cellEgressSuppressed`)

**File**: `SimPlayerController.{h,cpp}` — the `cellEgressSuppressed` member and its
`beginCellEgressIfNeeded` early-return already exist. Promote it from diagnostic-only
to the travel path: the departure collector-approach sets it; the arrival exit clears
it (so the egress leg runs). Invariant: set **only** for a directed move to a
portal-graph-reachable enclosed target, cleared before any "leave the building" move.
**Codex fix #9 — clear it in EVERY abort/reset path, not just the planned exit:**
add its reset to `clearCellEgressState()` (which is already called from
`prepareForRelocation`, `clearHybridMovementOnCancellation`, and
`resetIntelligentAssignmentForRecovery`), and clear it on travel cancel/abort/
completion and object destruction — otherwise a canceled/relocated/recovered bot keeps
`cellEgressSuppressed=true` and can never egress again.

### 3. Miner interplanetary travel → reach the collector, walk out on arrival

**File**: `SimPlayerController.cpp` (P.4.5b travel: `startInterplanetaryTravel` /
departure run, `boardInterplanetaryShuttle`, the travel arrival check, `onPathFailed`).

**Modifications**:
- **Departure:** on travel start, `resolveNearestTicketCollector` near the origin
  starport. If found: dismount (fix #3) → `moveToInterior(resolveStarportInteriorWaypoint)`
  to get inside → directed suppressed-egress move to the collector. Replace the ~20 m
  `travelBoardRadius`
  with `ticketCollectorBoardRadius` (~8 m) as a **real distance-to-collector** gate
  (fix #2): board only when `agent.worldPos.distanceTo(collector.worldPos) ≤ radius`
  **and** the bot shares the collector's containment (same hollow / not still deep
  in a cell) — not merely "path queue exhausted."
- **Bounded approach (fix #4):** track collector-approach attempts + a TTL; if the
  directed route stalls / `onPathFailed` fires before reaching the radius, re-approach
  up to the cap, then fall back to `boardInterplanetaryShuttle("collectorUnreachable")`.
  The current immediate-board-on-first-failure is replaced by this bounded path.
- **Arrival — owned by explicit travel phases (Codex fix #8):** the board teleport
  lands the bot at the destination hollow; the travel state machine then owns two
  new phases and does **not** report travel complete until the bot is outside:
  - `ARRIVAL_REENTER`: `moveToInterior(resolveStarportInteriorWaypoint at the
    destination starport)` — target is a cell, so `findPath(hollow → cell)`
    re-engages the portal graph.
  - `ARRIVAL_EGRESS`: on arrival inside, `moveTo(destination outdoor arrival)` with
    egress enabled → out the front.
  Only on reaching the outdoor arrival is travel marked complete and normal
  post-travel logic released. **Defer** the miner intelligent-assignment reset (and,
  for PvP, `beginCityLoop`/transit startup) until the bot is outside — otherwise those
  paths clobber the in-progress exit movement.
  - **PvP members must each exit themselves (Codex fix #12):** members land in the
    hollow too; relying on member-follow only after the leader is outside strands them
    (member and leader both `cell 0` → portal routing does not engage). Each member
    runs its **own** `ARRIVAL_REENTER`/`ARRIVAL_EGRESS`, and member-follow resumes
    only after every member is outside.
  - Result-driven (from the tri-state resolver): `WAYPOINT_FOUND` → run
    `ARRIVAL_REENTER`; `NO_INTERIOR` (genuinely outdoor starport, Dantooine-style) →
    skip re-enter and `moveTo` the outdoor arrival directly; `RESOLVE_FAILED` → retry
    under the bounded approach (do **not** treat as outdoor).
- Keep every existing safety gate (combat/dead/incapacitated, `isAvailableForDispatch`).

### 4. PvP mimetic travel → same collector approach

**File**: `SimPvPController.cpp` (`shuttleTargetIsCollector` / departure path).
Where the squad heads to a collector, use the resolver + directed interior approach
(suppress egress) with the same ~8 m real-distance gate and bounded fallback; keep
group cohesion/timing. Squads that only do intra-planet hops are unaffected.

### 5. Config + precedence (Codex fix #5)

**File**: `bin/scripts/managers/sim_player_manager.lua`

Add `ticketCollectorTravel = { enabled=false, boardRadiusMeters=8,
approachAttempts=3, approachTtlSeconds=60, fallbackToBoardFromNear=true,
testForceNoCollector=false }` (default **off**). **Precedence, explicit:** when
`enabled=false`, travel behaves
exactly as today (existing miner `planetDispatchBoardRadiusMeters` and PvP
`useCollectorBoarding` unchanged). When `enabled=true`, the effective board radius is
`ticketCollectorTravel.boardRadiusMeters` (overriding `planetDispatchBoardRadiusMeters`
for the interplanetary collector approach) and the collector approach + arrival exit
are active for both controllers; `fallbackToBoardFromNear` gates whether the bounded-
unreachable path may board from near (owner: yes). **Codex fix #10 — terminal
behavior when `fallbackToBoardFromNear=false`:** on approach exhaustion the travel is
**cancelled cleanly** — clear travel state (and `cellEgressSuppressed`), release the
bot to its normal idle/recovery path (miner: `resetIntelligentAssignmentForRecovery`;
PvP: squad recovery) — never left mid-travel or perpetually retrying. **Codex fix #6 —
deterministic no-collector fixture:** `testForceNoCollector=true` makes
`resolveNearestTicketCollector` return "none", exercising the fallback (or clean
cancel) path on ANY starport without hunting for a real no-collector one; a genuine
outdoor/shuttleport-only travel point can also be used if identified. Document this in
the config comments and the manager load.

### 6. Dismount-before-interior (Codex fix #3)

Vehicles are currently disabled (`enableVehicleMechanics=false`), but the code path
exists and entering a cell while parented to a vehicle risks the P.4.4 rider-orphan.
The departure leg **dismounts before the first `moveToInterior`**, not just before
boarding; assert no vehicle parent before any cell entry.

### 7. Diagnostic verification (harness stays until strip)

The `cellNavDiag` harness already proves the round trip (departure 1.79 m, arrival
2.84 m). Reuse it to smoke-test after wiring the real travel; then extend a
verification pass to a **real** miner/PvP bot traveling off-world through the
collector and walking out on arrival.

### 8. Strip diagnostic + release (executes the deferred F_0.4.9/F_0.4.10 strip)

Once real-bot travel verifies: strip **all** diagnostic scaffolding
(`CellNavDiagLog.h`, `cellNavDiag` config, `SimCellNavDiagController`, the
`resolveNearestTicketCollector`/`ENGINE_DIRECTION`/etc. diagnostic log lines, spawn/
resolver/retry, the diagnostic exit/return legs), **keeping** the real fixes
(`F_0.4.8`, `F_0.4.9`, `F_0.4.10`, `resolveNearestTicketCollector`, `cellEgressSuppressed`,
this travel capability), update `docs/ai-cell-navigation-design.md` +

## Technical Considerations

- **Pattern Usage**: composes proven primitives — `resolveNearestTicketCollector`
  (PvE-terminal pattern), `moveToInterior` (buff-provider pattern),
  `cellEgressSuppressed` directed route (validated live), `F_0.4.9` egress for the
  arrival exit, existing `boardInterplanetaryShuttle` teleport. No new movement
  primitive.
- **Locking & References**: collector world query holds no agent/manager lock
  (release-before-query, per `refreshProvider`); collector snapshot under its own
  short lock; travel state keeps the existing miner/PvP lock choreography;
  `cellEgressSuppressed` is controller-local state.
- **IDL Impact**: none — `isTicketCollector`, `asTangibleObject`, `getInRangeObjects`,
  `isInterplanetary` all exist.
- **C++ vs Lua Placement**: navigation/travel is C++; the gate/radius/attempts/TTL/
  fallback flags are Lua (`sim_player_manager.lua`), default off.
- **Gating & Simulation-Only**: gated (`ticketCollectorTravel.enabled=false`); travel
  remains a simulated `switchZone` reposition (no credit/ticket/inventory mutation);
  only *where the bot stands when it boards / after it lands* changes.
- **Codex fixes, tracked**: #1 topology → validated directed-route + re-enter/egress;
  #2 8 m gate → real distance + containment, not queue-exhaustion; #3 mounted →
  dismount before interior; #4 unreachable → bounded attempts/TTL before board-from-
  near; #5 config precedence → explicit effective radius/gate + disabled-unchanged;
  #6 fixture → verify fallback on a genuine no-collector travel point (below).
- **Dashboard Visibility**: optional travel-phase/collector field on the existing
  station-travel section; not required for the gated first cut.
- **Live Verification Plan**: diagnostic round trip (already green) + a real bot:
  off-world departure walks through to the collector (≤ 8 m) and boards; arrival
  walks out of the hollow to the world; and the bounded fallback fires on a genuine
  no-collector starport.
- **Edge Cases**: no-collector starport (bounded → board-from-near); Dantooine-style
  no-interior (collector outdoor → plain `moveTo`, no re-enter); collector reachable
  only via a long interior route (bounded attempts govern); combat en route (existing
  safety gates); mounted (dismount first); intra-planet mis-route (gate on
  `isInterplanetary`).
