# P.8.3 PvE Hunter Combat & Movement Realism Implementation Plan

## Overview

The PvE hunter economy loop is live-verified and working (114 kills, meat supply
climbing, mission lairs spawn/clean — branch `feat/pve-acquisition-demand-ledger`
commit `1df1850b83`). This pass fixes six owner-observed **realism/presentation**
bugs layered on that working loop so it becomes production-quality (the gate for
merging to `miner-ai`). None of these break the loop; they make hunters read as
real players: real ranged combat with retaliation, navmesh-aware city movement,
correct buffs/announcements, plus a dashboard live-position widget. Phased:
combat → movement → polish.

## Problem Statement (owner-observed in-game, 2026-07-18)

1. Hunter attacks **unarmed** despite an equipped rifle.
2. Target creature **does not retaliate** (one-sided).
3. Hunter **ignores city navmesh** — runs straight through buildings to the
   Mos Eisley shuttleport.
4. **Garbled announcement** — "A Hunter has moved out to the tatooine_womprat_meat
   hunting grounds Back with a full pack of meat" (two strings concatenated /
   wrong phase→message mapping).
5. **Buff step does not change HAM** — hunter visits the buff spot but
   health/action don't change.
6. **Teleport/skip/airborne movement** — position jumps and floats above terrain
   in the city, then drops to ground when it exits.

## Solution Architecture

- **Real combat (#1+#2)** — replace `SimHunterController::engageTarget`'s
  manual `addDefender`+`setCombatState` with **`CombatManager::startCombat(hunter,
  creature)`** (the real mutual-combat entry point that populates threat and
  triggers retaliation), and **align the hunter's weapon** so the AiAgent combat
  AI fires the rifle instead of falling back to unarmed. The existing Phase 2
  retreat/heal and death→clone→doctor paths handle the now-two-way fight.
- **Navmesh-aware movement (#3+#6)** — the SimController currently uses direct
  overland movement (correct in un-navmeshed wilderness where resources/lairs
  live) but keeps using it inside the navmeshed city, cutting through buildings
  and setting terrain height under building floors (the airborne glitch). Add a
  **movement mode switch keyed on `AiAgent::isInNavMesh()`** (owner's design):
  when the hunter is in / entering a navmeshed area (a city), traverse via
  `PathFinderManager::findPath` (navmesh nodes carry correct cell/height);
  when off-navmesh, keep direct overland. Detect the transition both ways so the
  hunter switches back to city traversal on return.
- **Polish (#4, #5)** — fix the announcement phase→message mapping/concatenation,
  and make the buff step actually change HAM (fill current, correct
  attribute/type). Plus a **frontend-only dashboard live-position widget** using
  the already-present `pveActivity.roster[].posPlanet/posX/posY/posZ` fields.

Everything stays **gated** behind the existing `pve`/`missionHunt` flags and
**simulation-only** for loot (real combat/real creatures, simulated harvest —
unchanged posture). Branch stays off `miner-ai` until the owner deems it
production-ready.

## Implementation Details

### 1. Real ranged combat (#1 + #2)

**File**: `MMOCoreORB/src/server/zone/objects/creature/simplayer/SimHunterController.cpp`
(+ hunter weapon setup in `SimPlayerManager.cpp:7594-7606`)

**Current state**: `engageTarget` (`:997-1025`) does `setTargetObject` +
`addDefender(target)` (both directions) + `setCombatState()`. It never issues a
real attack; kills come from the AiAgent default combat AI auto-swinging, which
selects its weapon via `equipPrimaryWeapon()`/`getPrimaryWeapon()`/`getWeapon()`
— Phase 2 only set `setDefaultWeapon`/`setCurrentWeapon`, not the primary the AI
uses, so it falls back to unarmed. `addDefender`+`setCombatState` does not create
real threat, so the creature never retaliates.

**Modifications**:

- **Weapon alignment**: in the hunter spawn/equip path, additionally make the
  equipped rifle the weapon the AI combat selects — set it as the primary weapon
  (`setWeapon`/`setPrimaryWeapon` per the AiAgent contract) and confirm
  `getWeapon()`/`getCurrentWeapon()` return the rifle after
  `equipPrimaryWeapon()`. Verify the rifle template exposes valid ranged combat
  (its `attackMap`/default ranged attack) so `selectSpecialAttack` has a ranged
  action; if the AI needs the mobile's `weapons`/`attacks` list to include the
  rifle's attack, populate it. (Implementation investigates the exact
  primary-vs-current-vs-attackMap interplay; plan-review focus.)
- **Real combat initiation**: in `engageTarget`, once in weapon range and the
  observer is registered, call `CombatManager::instance()->startCombat(agent,
  target)` (`CombatManager.h:123`) instead of the manual defender/combat-state
  set. `startCombat` establishes mutual combat + threat so the creature
  retaliates; the AiAgent combat AI then drives real rifle attacks. Keep the
  OBJECTDESTRUCTION observer for the kill→harvest hook.
- **Lock choreography**: match existing `startCombat` callers exactly (attacker
  lock; `startCombat` handles defender locking via `lockDefender`). Do not hold
  `pveMutex` across combat calls. This is the P.4.4-class risk area — mirror a
  known-good caller.
- **Damage handling**: the hunter can now take damage. Confirm the existing
  RETREAT (HAM threshold) and death→`CLONE_HOME` paths trigger from real damage
  (they already observe HAM/death); tune `retreatHamPct`/`resumeHamPct` if a
  two-way fight needs it. Simulated loot unchanged (harvest still typed
  `pve_hunter`).

### 2. Navmesh-aware movement mode switch (#3 + #6)

**File**: `SimPlayerController.{h,cpp}` (shared movement) and/or
`SimHunterController` travel legs

**Current state**: movement drives direct overland (terrain-following via
`zone->getHeight`, `SimPlayerController.cpp:853`); `PathFinderManager::findPath`
(`:44`) and `AiAgent::isInNavMesh()` (`:537`) already exist. Direct overland in a
navmeshed city cuts through buildings and places the body at terrain height
beneath building floors (airborne/teleport reads).

**Modifications** (hunter-opt-in — see Technical Considerations; default-off so
miners/PvP are unchanged):

- **Mode keyed on the AGENT's CURRENT position, not the destination (Codex P1).**
  `moveTo` calls `findPath`, which synthesizes a 2-node direct fallback when it
  can't evaluate a route (`PathFinderManager.cpp:458-462`) — but a legitimate
  straight Recast path can ALSO be 2 nodes, so node-count is not provenance.
  Decide mode from the agent's own `isInNavMesh()`: off-mesh ⇒ direct overland;
  the mode flips only when the agent itself enters the navmesh.
- **On-mesh legs use `getRecastPath` for explicit provenance (Codex P1).** While
  on-mesh, obtain the agent's `NavArea` (the nav-region lookup the miner
  NavArea-density sampler already uses) and call
  `PathFinderManager::getRecastPath(start, end, area, path, len, allowPartial)`
  (`PathFinderManager.h:69`) — its **`bool` return is the real success signal**
  (no node-count guessing). `true` ⇒ follow that navmesh path; `false` ⇒ it is a
  genuine navmesh failure (see recovery below), never the synthesized fallback.
- **Direction-aware legs + preserved final destination (Codex P1).**
  `getRecastPath` works within one `NavArea` and cannot reach an off-mesh point,
  so city→wilderness must be handled explicitly. Store the **final logical
  destination separately** (a `finalDestination` distinct from the current path
  endpoint) so the controller's destination-overwrite (`SimPlayerController.cpp:242`)
  can never make a mesh edge look like arrival, and only fire `onArrived` at
  `finalDestination`:
  - **On-mesh start, on-mesh dest** (e.g. within/into the city, to a terminal):
    `getRecastPath(..., allowPartial=false)` — the leg must fully reach the
    target; a partial is a failure (recovery), not arrival.
  - **On-mesh start, off-mesh dest** (city→wilderness lair): `allowPartial` can't
    help — `getRecastPath` first `findNearestPoly`s the *destination* and returns
    false for an off-mesh point (`PathFinderManager.cpp:262`). Resolve the exit
    boundary explicitly via `getNavMeshCollisions` (`PathFinderManager.h:76`), but
    **cast the ray from `finalDestination` toward `agentPos`** (outside→inside):
    an inside-origin ray (`agentPos`→dest) is discarded by the helper's `tca < 0`
    guard (`PathFinderManager.cpp:196`), so the reverse ray's boundary crossing is
    the reliable exit point. **Ground-snap** that point's Z via
    `getWorldFloorCollision(..., true)` before use (the existing caller does this
    at `PathFinderManager.cpp:356` — the reversed ray interpolates Z between dest
    and agent, so an unsnapped point can miss nearest-poly or target the wrong
    elevation). `getRecastPath(..., allowPartial=false)` to that snapped boundary
    point, then **overland** to `finalDestination`.
  - **Sanctioned egress (Codex P2).** Reaching the resolved exit boundary IS the
    confirmed navmesh-edge transition, so the "no overland while on-mesh" guard
    (below) is relaxed to: overland permitted when `!isInNavMesh()` **OR** the
    agent has reached the resolved exit boundary of the current logical move. The
    egress waypoint must be **validated as genuinely off-mesh (Codex P1)**: the
    `NavCollision.position` is at `0.975·radius` while `isInNavMesh()` stays true
    across the *whole* NavArea radius (`PathFinderManager.cpp:190`,
    `NavAreaImplementation.cpp:189`), so a small nudge can still be on-mesh.
    Probe outward toward `finalDestination` in bounded steps until a candidate
    passes terrain/water checks **and** the nav-region query returns **no**
    NavArea (confirmed off-mesh); use that as the egress waypoint. If no such
    point is found within the bound, fail/recover — do **not** authorize overland.
    Once the agent reaches the (off-mesh) egress waypoint, the debounce latches
    overland mode.
  - **Off-mesh start** (wilderness): direct overland; the debounced boundary
    re-path picks up navmesh traversal if/when the agent enters a navmesh area.
- **Debounced boundary re-path in `checkArrival` (Codex P1).** Track a latched
  `onMeshMode`. On each arrival tick sample `isInNavMesh()`; when it disagrees
  with `onMeshMode` for **`navmeshModeDebounceTicks` (default 2)** consecutive
  ticks, flip the latch and **force a re-path from the current position** (on:
  `getRecastPath`; off: direct overland). Reset the latch + debounce counter on:
  a new leg/`startOrder`, an accepted path, a relocation/`switchZone`, and
  arrival — so stale mode never carries across legs.
- **No overland inside the city (Codex P2).** On-mesh `getRecastPath` failure
  does **not** fall back to overland (that clips through buildings). Instead:
  bounded navmesh retries (`navmeshRepathTries`), then the existing controller
  recovery/`onPathFailed`/abort. Overland is permitted **only** when the agent is
  confirmed off-mesh (`!isInNavMesh()`) **or** it has reached the resolved exit
  boundary of the current move (the sanctioned egress above) — never mid-city on a
  navmesh failure.
- **Height fix (#6)**: on a navmesh path, take node heights from the `getRecastPath`
  nodes (not `zone->getHeight`), eliminating sub-floor/airborne placement;
  `getHeight` only on genuine overland legs. This co-occurs with the in-city
  direct-overland height error and is expected to resolve the airborne artifact.

### 3. Announcement mapping (#4)

**File**: `SimHunterController.cpp` (announce calls) +
`SimPlayerManager` PvE announcer

**Current state**: the observed string concatenates a "moved out to
<species> hunting grounds" line with a "Back with a full pack of meat" line —
the wrong message fires for the phase, or two templates are joined.

**Modifications**: give each hunter phase its own distinct announcement string
(depart/arrive-terminal/heading-to-lair/returning-with-harvest) and fire the
correct one per phase transition; remove the concatenation. Keep the announcer's
existing cooldown/site-gap. Text/config-tunable where practical.

### 4. Buff actually changes HAM (#5)

**File**: `SimHunterController::applyHunterBuffs` (`:~228`)

**Current state**: constructs a `Buff` with `setAttributeModifier(attribute,
modifier)` + `addBuff` under the `@preLocked` contract — but the owner sees no
HAM change. A positive `Buff` modifier already raises max HAM and heals by the
modifier (Codex P2), so an extra ad-hoc "fill" is not the right fix; the likely
real cause is that current isn't filled to the new max (the fill-on-apply flag
isn't set) and/or the attribute/type mapping isn't producing a visible pool
change.

**Modifications**: use the proven **`buff->setFillAttributesOnBuff(true)`** so the
current pool fills on application, and define the invariants: first application
increases max by `modifier` and current reaches `max - wounds`; a refresh
**replaces** (no stacking). Verify the `attribute`/`buffType` map to real HAM
pool constants and the buff persists on the AiAgent. Keep it simulation-safe (no
economy mutation).

### 5. Dashboard live-position widget (owner request)

**Current state**: `pveActivity.roster[].posPlanet/posX/posY/posZ` (+ phase) are

Frontend-only, instant `docker cp` deploy, no server restart, respects the
existing whitelist/no-build-step constraint.

## Technical Considerations

- **Pattern Usage**: `CombatManager::startCombat` mirroring an existing caller
  (combat); `PathFinderManager::findPath` + `isInNavMesh` mirroring the miner
  navigation/path-validation code; the dashboard SPA pattern (3 static files).
- **Locking & References**: combat initiation matches a known `startCombat`
  caller's lock order (attacker locked; defender via `lockDefender`); movement
  changes stay within the existing SimController lock discipline; no `pveMutex`
  held across combat/zone calls. Combat + movement are the P.4.4-class risk
  areas — mirror proven callers exactly.
- **IDL Impact**: none expected (calling existing native combat/pathfinding
  APIs; no new `.idl` fields). Confirm during implementation.
- **Hunter-opt-in movement (Codex P2)**: the navmesh/overland hybrid lives in
  shared `SimPlayerController` but must be **opt-in** — guard it behind a virtual
  `usesNavmeshHybridMovement()` (or a controller flag) defaulting **false**;
  only `SimHunterController` returns true. Miners and PvP squads keep their exact
  current movement (no behavior change when PvE is off or for non-hunters).
- **C++ vs Lua Placement**: combat/movement logic in C++; announcement text and
  any new tunables (retreat pct) in Lua; widget in the SPA.
- **Gating & Simulation-Only**: all behind the existing `pve`/`missionHunt`
  gates; loot stays simulated. Real combat really kills creatures (intended) and
  can kill the hunter (→ existing clone path) but mutates no economy/inventory.
- **Dashboard Visibility**: reuse the existing `pveActivity` fields; the widget
  is the new surface. Combat/movement verified via kills + in-game observation.
- **Live Verification Plan**: rebuild, restart, watch in-game at the live
  `posX/posY` + dashboard: (1) hunter **fires its rifle** (ranged), creature
  **retaliates**, fight is two-way; (2) hunter takes damage → retreats/heals or
  dies→clones under a losing fight; (3) hunter **follows city streets** (no
  building clipping) and **stays on the ground** (no airborne/teleport); (4) the
  announcement reads correctly per phase; (5) HAM visibly rises at the buff step;
  (6) the dashboard widget shows all six bots' live positions. `hunterKillsTotal`
  keeps climbing (loop unbroken).
- **Edge Cases**: creature pack retaliation overwhelming a low-tier hunter
  (retreat/abandon/clone must hold — verify no death spiral); navmesh
  `getRecastPath` failure in a city (bounded retries → controller recovery/abort,
  NEVER overland-through-buildings; no strand); rifle out of
  range/ammo-less (ranged attack still resolves as sim combat); buff re-applied
  each contract (no stacking runaway); widget with a bot mid-zone-transition
  (blank pos handled).

## Type Definitions

- No new persistent types. Controller movement-mode state: `bool onMeshMode` +
  `int navmeshModeDebounceCounter` (the mode latch — reset on new leg,
  accepted path, relocation, arrival). Separately, `Vector3 finalDestination`
  (the preserved logical target, distinct from the current path/subleg endpoint):
  **set once per logical move, cleared only on FINAL arrival, cancellation, or
  relocation — NOT on subleg/boundary-path acceptance** (Codex — it must survive
  the exit-boundary subleg completion). A virtual `bool
  usesNavmeshHybridMovement()` (base false, SimHunterController true).
- New `SimPlayerManager` config members + getters (guarded/loaded like existing
  pve config): `int pveNavmeshModeDebounceTicks = 2;`, `int pveNavmeshRepathTries
  = 3;` (explicit bounded default for missing/invalid Lua) — set in
  `applyPveConfig` (clamped) from Lua `missionHunt.navmeshModeDebounceTicks` /
  `navmeshRepathTries`, read by the controller. Per-phase announcement
  keys/strings (§3).

## Performance & Cost Impact

- `findPath` in cities is invoked per travel leg (not per tick) — bounded, same
  cost class as existing miner pathing. `startCombat` is one call per engage.
  `isInNavMesh` checks are O(1). No new population-scale work.
