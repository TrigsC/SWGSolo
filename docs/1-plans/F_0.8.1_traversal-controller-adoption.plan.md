# F_0.8.1 — Traversal adoption by production controllers (plan)

**Status: PLAN.** Two fixes already implemented on
`feat/f081-traversal-controller-coverage`; the migration below is not.

## 1. The finding that defines this work

`enterStructure()` — the function that builds a `StructureTraversalIntent`, sets
the phase and emits `ST_PHASE` — has **exactly one caller in the codebase**:

```
SimPlayerController.cpp:5262   SimTraversalTestController::issueResolvedStep
```

**No production bot type uses the structure traversal state machine.** Miners,
hunters, PvP leaders and PvP members all reach buildings through `moveTo` or
`moveToInterior`, neither of which starts a traversal. F_0.8.0's foundation is
exercised only by its own harness.

This is not a defect in that release — it shipped default-off and was verified
through the matrix — but it is the whole answer to "how do I make every bot type
use this": they must be migrated, and none have been.

Corollary: the D2b far-side-egress predicate is guarded by
`isTraversalActive() && structureTraversalIntent.exitIntent`. Until a controller
calls `enterStructure`, D2b **cannot fire for it**, no matter how the path
acceptance chain is wired.

## 2. Already implemented (safe, no behaviour change pending verification)

### 2.1 Path acceptance is now a template method

`SimPlayerController::acceptFoundPath` is **non-virtual**. It runs
`acceptFoundPathInvariants()` (P.6.1b stale-path defense + D2b) and then the new
`virtual acceptFoundPathHook()`. `SimPvPController` previously overrode
`acceptFoundPath` wholesale and never chained, silently opting PvP leaders out
of every base invariant; it now implements the hook. A future controller that
tries to override the invariants gets a **compile error**.

Inert for PvP until §3 lands, but it is the structural guarantee the owner
asked for and it protects controllers that do not exist yet.

### 2.2 Cell-local coordinate fix at both collector approaches

`SimPvPController.cpp:1287` and `:1481` passed `collectorWorld` as the
**local** argument. `resolveNearestTicketCollector` sets
`outLocal = outCell != nullptr ? best->getPosition() : outWorld`, so for a
collector baked **inside a starport cell** that argument must be cell-local.
Passing the world point is the F_0.4.7 world-coord-as-cell-local class ARCHI §12
warns about; it is masked today because hollow collectors make the two equal.
Now uses `collectorLocal` — a no-op outdoors, a correction in the reachable case.

## 3. The migration (NOT implemented — the risky part)

Candidate sites, all currently non-traversal:

| site | call today | genuine building entry? |
| --- | --- | --- |
| `SimHunterController.cpp:496` | `moveToInterior` | yes — med centre / cantina buff provider |
| `SimPvPController.cpp:1274` | `moveToInterior` | yes — starport interior waypoint |
| `SimPvPController.cpp:1342` | `moveToInterior` | yes |
| `SimPvPController.cpp:2022` | `moveToInterior` | yes — arrival exit |
| `SimPvPController.cpp:1287` | `moveTo(...,cell)` | only when `collectorCell != nullptr` |
| `SimPvPController.cpp:1481` | `moveTo(...,cell)` | only when `collectorCell != nullptr` |

Migration is `enterStructure(world, local, cell)` **guarded on a non-null cell**;
a null cell stays an outdoor approach, which is required by the owner's standing
constraint that a hollow is frequently the destination.

`enterStructure` already degrades safely: with `structureTraversal.enabled =
false` it falls straight through to `moveToInterior`, i.e. today's behaviour
exactly. So the migration is inert until the gate is on.

## 4. Verification — why not the matrix

The harness cannot drive a production controller. `issueResolvedStep`,
`setHarnessForcePathFailure`, `setHarnessEgressSuppressed` and
`isHarnessOutdoorsClearFor` all live on `SimTraversalTestController`; driving a
real PvP bot through matrix steps would mean moving test-only methods onto the
production base class, and the PvP phase machine would fight the harness anyway.

**The gate instead is the traversal trace itself.** `StructureTraversalDiagLog`
keys every `ST_PHASE` line by agent OID. A migrated PvP or hunter bot emits real
phase traces where today it emits nothing at all, so the assertion is direct and
cannot pass vacuously:

| # | Assertion |
| --- | --- |
| A1 | Server starts clean, `core3` alive, no crash/backtrace |
| A2 | **PvP squad agent OIDs appear in `ST_PHASE` lines** — the migration is live, not merely compiled |
| A3 | Phases are ordered per agent (`ApproachDoor → InteriorRoute`; `Egress` only from inside) |
| A4 | Zero `ST_FAIL reason=path_failed` attributable to a migrated leg |
| A5 | Anomaly counters flat: `teleportsDetected`, `zSanityViolations`, `resumeFailures` deltas 0 |
| A6 | PvP travel still completes — squads reach shuttles/collectors, no phase stall past its TTL |
| A7 | Regression guard: the 26-scenario matrix still returns 22 PASS / 4 FAIL |
| A8 | Cleanup: gates restored, no bots leaked |

A2 is the non-vacuity check that the D2b work lacked until it was caught.

Config profile: `structureTraversal.enabled/logging = true` plus the existing
default-on `pvpConfig.enablePvpBots` and `ticketCollectorTravel.enabled`. This is
a **different profile** from the traversal matrix, so it is a fresh run either
way; A7 needs its own matrix pass.

## 5. Risk

Migrating turns on a state machine that has **never run for PvP or hunters**.
The traversal machinery assumes it owns movement for the leg — phase, generation,
escalation, egress. PvP has its own phase machine (`PVP_TO_SHUTTLE` etc.) and
hunters their own hunt loop. `isInteriorTraversalActive()` exists on the PvP side
precisely so combat yields to traversal, which suggests the interaction was
anticipated, but it has not been exercised.

Recommended sequencing, smallest blast radius first:

1. **Hunters only** (`SimHunterController.cpp:496`) — one site, a buff-provider
   walk, no travel choreography entangled. Verify A1-A8.
2. **PvP collector approaches** (`:1287`, `:1481`) — cell-guarded, and the flow
   the owner cares about for multi-hop transit.
3. **PvP starport waypoints** (`:1274`, `:1342`, `:2022`) — most entangled with
   `PVP_TO_SHUTTLE` phase state; do last, on its own run.

Doing all six at once would make an A6 failure ambiguous about which site caused
it.
