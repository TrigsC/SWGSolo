# P.6.5d City-Loop Realism + Squad Cohesion Implementation Plan

## Overview

Two owner-reported live gaps after P.6.5b: (1) at every city except Theed the
entire city loop (arrive → hangout → depart) collapses onto the starport, so
squads visibly "stand around the port and hop on" — and intra-planet legs
never use real city shuttleports; (2) squads that take deaths en route to a
hangout keep feeding replacements/promoted leaders into the same killzone one
clump at a time until wiped. This plan separates the three per-city locations
(starport / city shuttleport / hangout) using live travel-point data, adds
cantina-derived hangouts with Lua override (owner decision: Mixed), and adds
a break-off-after-deaths cohesion behavior (owner decision: break off and
route elsewhere; convergence machinery is the counter-gank answer).

Owner decisions (2026-07-14 discovery):
- **Hangouts: Mixed** — cantina-derived defaults resolved from live objects,
  per-city Lua manual override honored when set.
- **Anti-gank: break off after N deaths** — abort the city, regroup, route to
  a different city; no push-together retry mode.

## Problem Statement

- Config conflation (evidence): the six P.6.5a-added cities' `spawn`
  coordinates equal their **starport** coordinates exactly (e.g. bestine
  spawn `{-1361.2,-3600.0}` == "Bestine Starport"), and 6/10 configured
  hangouts are ≤31m from spawn. Legacy cities (theed/moenia/mos_eisley/
  coronet) have spawn = city shuttle pad, hangout = near the starport. Only
  Theed's 560m shuttle→hangout run is visible.
- After a cross-planet arrival the squad's stored pad (`squad.shuttlePos`)
  becomes the STARPORT pad it landed on; a following intra-planet first leg
  departs from `snapshot.shuttlePos` (SimPlayerManager.cpp leg building) —
  so Mos Eisley→Bestine "shuttles" from the starport, never the city
  shuttleport. Intra arrivals land on `loc.spawn`, which for new cities is
  again the starport.
- Deaths during PVP_TO_HANGOUT/PVP_LOITERING never abort the city: promotion
  re-drives the same run to the same hangout (SimPvPController phase
  machine), replacements refill at the next travel — a gank camp defeats a
  squad piecemeal with no behavioral response.
- Enabler (verified in repo data): every configured city has a named
  NON-interplanetary `PlanetTravelPoint` ("Bestine Shuttleport", "Coronet
  Shuttle B", "Mos Entha Shuttle A", ... —
  `bin/scripts/managers/planet/planet_manager.lua`) resolvable via the same
  `getPlanetTravelPoint(name)` lookup the starports already use. No IDL
  change, no octree scans, no hand-typed coordinates for pads.

## Solution Architecture

1. **Three explicit per-city locations.** `ShuttleportLocation` gains a
   `shuttlePoint` (exact intra-planet PlanetTravelPoint name, from Lua, like
   the existing `starportPoint`) resolved at plan/board time to the city
   shuttle pad. Semantics become: **starport pad** (live data via
   `starportPoint`) for cross-planet arrivals + collector departures; **city
   shuttle pad** (live data via `shuttlePoint`) for intra-planet departures
   AND arrivals; **hangout** for loitering. `loc.spawn` remains only as
   spawn placement + fallback when a point name fails to resolve.
2. **Hangout resolution (Mixed).** Per city: if Lua sets `hangoutManual =
   true`, the configured `hangout` is authoritative. Otherwise resolve the
   nearest cantina to the city shuttle pad from live objects (octree scan
   for building objects whose server template path contains "cantina",
   radius ~400m, cached like boarding points). The hangout point must be a
   **validated exterior spot**, never a raw center offset (cantinas are
   multi-cell collision buildings — an arbitrary offset can land inside the
   structure): candidate = the cantina's world position displaced TOWARD
   the shuttle pad by (template `boundingRadius` + ~8m margin), then
   validated by **explicit navmesh membership**, not path shape — this
   project's P.4 rule says a non-null `findPath` result is NOT validation
   (synthetic start/end fallback, PathFinderManager.cpp:459), and node
   count cannot discriminate either (Detour's `findStraightPath`
   legitimately returns just start+end for an unobstructed multi-polygon
   route). A candidate passes when:
   (a) `zone->getInRangeNavMeshes(candidateX, candidateY, &areas, false)
   > 0` — the same position-based query backing `SceneObject::isInNavMesh`
   (SceneObjectImplementation.cpp:2272) — i.e. the point provably lies in
   the city navmesh; and (b) it sits outside the cantina's collision
   footprint (distance from the building's world position ≥
   boundingRadius). `findPath(shuttle pad → candidate)` is then run only
   to obtain the walk-in point — the **path end** becomes the stored
   hangout (and `hangoutPathNodes` records the size for the dashboard) —
   never as the validator. On failure, try the 4 cardinal ring points at
   the same radius (same two checks); all candidates fail →
   configured-hangout fallback. Resolution is cached and deterministic.
   Dashboard rows expose per-city resolved source
   (`manual|cantina|fallback`) + position + pathNodes so every city is
   verifiable before trusting the feel.
3. **Leg targets corrected.** In `planPvpRoute` leg building: intra legs
   depart from the departure city's **shuttle pad** and arrive at the
   destination's **shuttle pad** (replacing both the `snapshot.shuttlePos`
   first-leg shortcut and the 0.2.0 `loc.spawn` arrival); cross-planet legs
   keep starport arrival + collector/starport-pad departure (P.6.5b,
   unchanged). `onPvpSquadDepartureIntent` returns the intra shuttle pad for
   intra first legs — the squad runs across town to the real shuttleport.
4. **Break-off cohesion.** The manager already learns every bot death
   (`onPvpBotDied`). Deaths are tracked as a **rolling window** (not
   anchored to city-loop start): per squad, `recentDeathCount` +
   `recentDeathWindowStartMs`; a death outside the window restarts it
   (count=1), inside increments. Both reset at initial spawn and on arrival
   at a new city, so staging ganks count correctly and late ganks (after
   the squad has loitered a while) still trigger. When the count reaches
   `breakOffDeaths` (default 2) within `breakOffWindowSeconds` (default
   120) while the squad is in TO_HANGOUT/LOITERING/TO_SHUTTLE, the squad
   **breaks off** — and the decision is **latched** (`breakOffPending`,
   single-shot per city): if the leader is alive, immediate interrupt (halt
   + `enterToShuttle`, the convergence choreography); if the threshold
   death WAS the leader, the pending latch survives and **leader promotion
   honors it** — the promoted leader drives the break-off departure instead
   of re-entering `beginCityLoop` toward the same hangout. The latch also
   suppresses duplicate break-offs from further deaths during the
   departure; it clears only on arrival at another city. Alongside the
   latch: a RETREAT announce (new event, faction-flavored lines) and a
   per-squad `avoidPlanet/City` stamp (`avoidCitySeconds`, default 600)
   that the destination pick skips — the replan cannot pick the killzone
   again. Deaths there were already reported as contacts, so a *different*
   squad converges as the answer. Counters: `breakOffsTotal`; log
   `SimPvpSquadBrokeOff squad= city= deaths= leaderAliveAtTrigger=`.

## Implementation Details

### 1. SimPlayerManager.h

**File**: `MMOCoreORB/src/server/zone/objects/creature/simplayer/SimPlayerManager.h`

**Modifications**:

- `ShuttleportLocation` += `String shuttlePoint;` (exact intra-planet travel
  point name) and `bool hangoutManual = false;`.
- New cached per-city resolved-locations struct (shuttle pad Vector3 +
  resolved flag; hangout Vector3 + source enum manual|cantina|fallback) in a
  `VectorMap` keyed by planet:city, guarded by `pvpSquadMutex` (scan outside,
  store under — the boarding-point pattern).
- `SimPvpSquad` += rolling-window death tracking (`int recentDeathCount`,
  `uint64 recentDeathWindowStartMs` — reset at spawn and city arrival), the
  single-shot `bool breakOffPending` latch, and avoid stamp
  `String avoidPlanet, avoidCity; uint64 avoidExpiresAtMs`.
- Config members: `pvpBreakOffEnabled` (C++ default false),
  `pvpBreakOffDeaths` (2), `pvpBreakOffWindowSeconds` (120),
  `pvpAvoidCitySeconds` (600), `pvpUseCantinaHangouts` (C++ default false),
  `pvpCantinaScanRadiusMeters` (400).
- Counter `pvpBreakOffsTotal`; new announce enum value
  `PVP_ANNOUNCE_RETREAT`; method decls: city-locations resolver, break-off
  check hook.

### 2. SimPlayerManager.cpp

**File**: `MMOCoreORB/src/server/zone/objects/creature/simplayer/SimPlayerManager.cpp`

**Modifications**:

- **City-locations resolver**: shuttle pad via
  `planetManager->getPlanetTravelPoint(loc.shuttlePoint)` (fallback
  `loc.spawn`, log on failure — mirrors the starport resolve in
  `planPvpRoute`); cantina hangout via octree `getInRangeObjects` around the
  shuttle pad filtering building objects whose
  `getObjectTemplate()->getFullTemplateString()` contains "cantina"
  (read-only static snapshot objects, the collector-scan pattern); honor
  `hangoutManual`; cache both.
- **`planPvpRoute`**: intra legs — `arrivalPos` = destination city's
  resolved shuttle pad; departure fields = departure city's resolved shuttle
  pad (drop the `snapshot.shuttlePos` first-leg shortcut for intra legs;
  cross-planet legs keep P.6.5b behavior). Destination pick and tactical
  alternate pick skip a city matching the squad's unexpired avoid stamp.
- **`boardPvpSquad`**: final-leg `beginCityLoop` hangout = resolved hangout
  (not raw `loc.hangout`); on arrival at a new city reset
  `recentDeathCount`/`recentDeathWindowStartMs` and clear `breakOffPending`.
  Spawn sites (`spawnPvpSquad`) initialize the window fields too, so
  staging-city ganks count from the first death.
- **`onPvpBotDied`**: after the existing bookkeeping, roll the window (death
  outside `breakOffWindowSeconds` of `recentDeathWindowStartMs` → restart
  count at 1; inside → increment). If `pvpBreakOffEnabled`, count ≥
  threshold, phase in TO_HANGOUT/LOITERING/TO_SHUTTLE, and NOT already
  `breakOffPending`: **latch `breakOffPending`**, stamp avoid city,
  `pvpBreakOffsTotal++`; then if the leader controller is alive, RETREAT
  announce followed by `interruptForBreakOff()` (convergence choreography,
  no stamp; departure intent plans a fresh route which the avoid stamp
  steers away). If the threshold death WAS the leader, announce NOTHING
  here — the announcer drops events from dead leaders
  (SimPlayerManager.cpp:23584) — and **leader promotion consumes the
  latch**: the promotion path checks `breakOffPending`, speaks the RETREAT
  line through the freshly promoted (alive) leader, and drives it through
  `interruptForBreakOff()` instead of `beginCityLoop`. The latch suppresses
  duplicate triggers from further deaths during the departure; already
  AWAITING_SHUTTLE/boarding → early-return (squad is leaving anyway).
- **Announce lines**: 3 faction-flavored RETREAT lines in
  `pickPvpAnnounceLine` ("Fall back to the shuttle!", ...); RETREAT bypasses
  **both** the per-squad cooldown AND the global gap — in a real gank a
  CONTACT shout fires seconds before the deaths, and a suppressed retreat
  callout defeats the feature's whole purpose. RETREAT is rare (latched
  once per city) so the anti-spam risk is nil.
- **Config parse** (`applyPvpConfig` travel/new `cohesion` block) +
  **dashboard**: `routedTravel` += breakOffsTotal, cantina/shuttle-pad cache
  rows with per-city source; per-squad avoidCity + recentDeathCount.
- **Lua config load**: read `shuttlePoint`/`hangoutManual` per city.

## Technical Considerations

- **Pattern Usage**: point-name resolution copies the P.6.5a `starportPoint`
  pattern; cantina scan copies the P.6.5-0 collector-scan pattern; break-off
  interrupt copies `interruptForConvergence`; avoid stamp copies the
  convergence stamp shape (string pair + expiry under `pvpSquadMutex`).
- **Locking & References**: no new lock orders. Resolver scans outside
  `pvpSquadMutex`, caches under it; `onPvpBotDied` already runs manager-side
  with established locking — the break-off decision reads squad state under
  the mutex, RELEASES it, then announces and nudges the controller (the
  mutex is never held while locking agents, existing rule).
- **IDL Impact**: none — `getPlanetTravelPoint` is an existing public lookup;
  no PlanetManager accessor additions needed.
- **C++ vs Lua Placement**: all thresholds/gates in Lua; point names are
  data in Lua; C++ only resolves and executes.
- **Gating & Simulation-Only**: `useCantinaHangouts` and `cohesion.breakOff`
  both C++-default-off; off restores exactly current (0.2.1) behavior except
  the leg-target correction (intra legs at real shuttleports) which is an
  unconditional correctness fix, called out here for rollback honesty (the
  gated-off legacy path is untouched). Read-only world data; no player-state
  writes.
- **Dashboard Visibility**: per-city resolution table is the acceptance
  instrument — every city's hangout source/pos inspectable before feel
  verification.
- **Live Verification Plan**: §13.3-style checklist (below in Test Impact);
  primary signals: intra legs visibly run shuttle pads, hangout runs at all
  10 cities, `SimPvpSquadBrokeOff` under a staged gank, breakOffsTotal,
  avoided city not re-picked within the window.
- **Edge Cases**:
  - `shuttlePoint` typo/missing → resolve fails → `loc.spawn` fallback +
    log (city keeps working at P.6.5b fidelity).
  - No cantina within radius (restuss?) → configured-hangout fallback,
    source visible on dashboard.
  - Break-off while already AWAITING_SHUTTLE → early-return (squad is
    leaving anyway).
  - Break-off route planning finds ONLY the avoided city acceptable
    (single-city planet) → avoid stamp is a preference in the pick loops,
    never a hard filter on the last-resort pass — never wedges.
  - Whole-squad wipe before threshold (or after the latch, before
    departure) → existing reform machinery unchanged; reform drops the
    squad row and its latch with it.
  - Avoid stamp expiry mid-route → harmless (stamp only consulted at pick).
  - Staging spawns (moenia/bestine) → window fields initialized at spawn; a
    staging gank triggers break-off correctly.
  - Threshold death kills the leader → latch survives; promotion drives the
    break-off departure instead of re-running the same hangout.

## Performance & Cost Impact

- One `getPlanetTravelPoint` lookup + one cached cantina scan per city
  (≤10), once per boot/config-change — collector-cache cost class.
- Break-off check is O(1) work inside the existing death callback.

## Backward Compatibility

- `useCantinaHangouts=false` + `cohesion.breakOff=false` → current 0.2.1
  behavior except intra legs using real shuttleports (unconditional
  correctness fix, documented above).
- Legacy (routed-travel-off) path untouched.
- Miners unaffected (no shared-base changes in this plan).
