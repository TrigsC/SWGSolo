# Doctor/Entertainer Buffer Player-Chat Crash Fix Implementation Plan

## Overview

Talking to the Smart Doctor Buffer NPC as a real player hard-crashes the
server (SIGABRT). The P.8.6 "PvE bots get buffs from doctors" work
(`F_0.4.6`) added a `isSimPlayerBot()` gate to the doctor's chat handler that
wraps the *speaker* as `AiAgent(pObj)`. When the speaker is a real player
(not an `AiAgent`), that wrap trips a debug-build assertion in
`LuaAiAgent::_setObject` and calls `abort()`. This plan makes every
sim-bot check safe: a C++ hardening that exposes `isSimPlayerBot()` on
`LuaCreatureObject` (returns false for non-agents, never asserts), plus Lua
guards in the three custom buffer scripts that adopt it.

## Problem Statement

- Speaking a buff request to the Smart Doctor Buffer as a human player aborts
  the zone process. Reproduced by the owner; GDB backtrace supplied.
- The crash is a regression introduced with the doctor→PvE-bot buff feature
  (P.8.6 / `F_0.4.6`), exactly matching the owner's recollection that "something
  broke when we implemented the pve bots getting buffs from doctors."

### Root cause (confirmed from source + backtrace)

1. `ChatManagerImplementation::broadcastChatMessage` fires the
   `SPATIALCHATSENT` (event 50) observer on the **speaker** object
   (`src/server/chat/ChatManagerImplementation.cpp:1104`).
2. That observer is `AiGlobalChatHandler:notifySpatialChatSent`
   (`bin/scripts/screenplays/custom/aiGlobalChatHandler.lua:291`), which for a
   `smart_doctor` profile calls
   `SmartDoctorBuffer:handleChat(pTarget, pPlayer, msg)` inside a `pcall`
   (line 353).
3. `handleChat` reaches `isSimPlayerBot(pSpeaker)` on the IDLE→NEGOTIATING
   path (`smartDoctorBuffer.lua:1100`). The helper
   (`smartDoctorBuffer.lua:242`) does, **unconditionally**:
   `return AiAgent(pObj):isSimPlayerBot()` (line 246).
4. `AiAgent(pObj)` is `Luna<LuaAiAgent>::Register`'d
   (`DirectorManager.cpp:894`); constructing it runs
   `LuaAiAgent::_setObject`. In this **debug build**
   (`DYNAMIC_CAST_LUAOBJECTS` defined),
   `realObject = dynamic_cast<AiAgent*>(_getRealSceneObject())` is `nullptr`
   for a player, so
   `E3_ASSERT(!_getRealSceneObject() || realObject != nullptr)` fails
   (`LuaAiAgent.cpp:182`) → `sys::e3_assert_internal` → `abort()` → SIGABRT.
5. **The surrounding `pcall`/`safeCall` wrappers cannot save this**: `abort()`
   is a process-level signal, not a catchable Lua error. The three nested
   `lua_pcallk` frames in the backtrace (observer `callFunction` →
   `pcall(handleChat)` → `pcall` inside `isSimPlayerBot`) confirm the exact
   path.

The safe pattern already exists in the codebase: `ai_registry.lua:110` uses
`SceneObject(pCreature):isAiAgent()` (a plain virtual call, no cast, never
asserts), and `smart_entertainer_helper.lua` checks `isPlayerCreature()`
*before* wrapping — which is why the doctor crashes on players but the
musician/dancer usually do not. The doctor helper has no such guard.

### Why a release build would also be wrong

Under a non-debug build (`static_cast<AiAgent*>(lua_touserdata(...))`) the wrap
would not assert but would produce a mis-typed pointer and call
`getSimPlayerBot()` through it — undefined behavior. The debug assertion is
surfacing a real latent bug, so the fix is correct for both build types.

## Solution Architecture

Two coordinated layers (owner-selected "Lua guard + C++ hardening"):

1. **C++ (defense-in-depth, kills the bug class):** add an `isSimPlayerBot`
   method to `LuaCreatureObject` that resolves the agent via the existing
   native safe cast `CreatureObject::asAiAgent()` (returns `nullptr` for
   non-agents — no `dynamic_cast`, no assertion) and returns
   `agent->getSimPlayerBot()`, else `false`. After this, Lua can ask *any*
   creature whether it is a sim bot without ever wrapping `AiAgent()`.

2. **Lua (adopt the safe path in all three custom buffers):** replace each
   unguarded `AiAgent(pObj):isSimPlayerBot()` with a guarded call that (a)
   confirms the object is a creature via the always-safe
   `SceneObject(pObj):isCreatureObject()` and (b) uses the new
   `CreatureObject(pObj):isSimPlayerBot()`. Real players and non-creatures
   return `false`; sim bots return `true`; behavior for actual bots is
   unchanged.

No new feature, no config gate (this restores previously-correct behavior and
removes a crash). Simulation-only posture is untouched — no
inventory/credit/market mutation is added or altered.

## Implementation Details

### 1. Expose `isSimPlayerBot` on `LuaCreatureObject` (C++)

**File**: `MMOCoreORB/src/server/zone/objects/creature/LuaCreatureObject.h`

**Modifications**:
- Declare `int isSimPlayerBot(lua_State* L);` (non-static instance member,
  matching the existing `int isAiAgent(lua_State* L);` — Luna binds an
  instance-member pointer and the impl reads the instance member `realObject`)
  next to `isAiAgent` (around line 80).

**File**: `MMOCoreORB/src/server/zone/objects/creature/LuaCreatureObject.cpp`

**Current state**: registers `{ "isAiAgent", &LuaCreatureObject::isAiAgent }`
(line 99) and implements `isAiAgent` (line 790) as
`realObject->isAiAgent()`. `realObject` is a `CreatureObject*`. The file
already references `AiAgent`/`asAiAgent` (3 sites).

**Modifications**:
- Add `{ "isSimPlayerBot", &LuaCreatureObject::isSimPlayerBot }` to the
  `luaL_Reg` method table (adjacent to the `isAiAgent` entry, ~line 99).
- Implement `isSimPlayerBot` mirroring `isAiAgent`'s shape: guard
  `realObject != nullptr`, obtain `AiAgent* agent = realObject->asAiAgent();`
  (native safe cast, `nullptr` for non-agents), push
  `agent != nullptr && agent->getSimPlayerBot()`. This reuses exactly the
  accessor `LuaAiAgent::isSimPlayerBot` already calls
  (`realObject->getSimPlayerBot()`, `LuaAiAgent.cpp:1027`).
- Ensure `AiAgent`'s full definition is visible for the `getSimPlayerBot()`
  call — add `#include "server/zone/objects/creature/ai/AiAgent.h"` if it is
  not already transitively included (the build will flag an incomplete-type
  error if missing; `-Werror`/clean-build gate catches this).

No IDL change: `asAiAgent()` (`SceneObject.idl:1577`) and the `simPlayerBot`
field's generated `getSimPlayerBot()` accessor (`AiAgent.idl:1278`) already
exist.

### 2. Guard the Smart Doctor Buffer helper (Lua — the actual crash)

**File**:
`MMOCoreORB/bin/scripts/screenplays/custom/smartDoctorBuffer.lua`

**Current state** (line 242-250):
```
local function isSimPlayerBot(pObj)
    if pObj == nil then return false end
    local ok, isSimBot = pcall(function()
        return AiAgent(pObj):isSimPlayerBot()   -- line 246: unsafe wrap
    end)
    return ok and isSimBot == true
end
```

**Modifications**:
- Rewrite the helper body to guard with `SceneObject(pObj):isCreatureObject()`
  (always-safe) and then call the new `CreatureObject(pObj):isSimPlayerBot()`.
  Keep the `nil` guard and the `pcall` belt-and-suspenders. No other call site
  changes — all ten `isSimPlayerBot(...)` callers route through this one helper.

### 3. Harden the entertainer helper (Lua — latent sibling)

**File**:
`MMOCoreORB/bin/scripts/custom_scripts/smart_entertainer_helper.lua`

**Current state** (line 27-38): `isValidAudienceMember` checks
`isPlayerCreature()` first (which spares real players) and only then does
`AiAgent(pPlayer):isSimPlayerBot()` (line 34) — unsafe for a non-player,
non-agent creature.

**Modifications**:
- Replace the `AiAgent(pPlayer):isSimPlayerBot()` fallback with the same
  `isCreatureObject()`-guarded `CreatureObject(pPlayer):isSimPlayerBot()`
  pattern. Preserve the existing player-first short-circuit and `pcall`.

### 4. Harden the heal-wrap in the global chat handler (Lua — latent sibling)

**File**:
`MMOCoreORB/bin/scripts/screenplays/custom/aiGlobalChatHandler.lua`

**Current state** (line 486):
`safeCall(nil, function() LuaAiAgent(pTarget):healCreatureTarget(pPlayer) end)`
inside the legacy skill handler — reached only when a profile's `skills`
table maps a keyword to `cpp_function == "healCreatureTarget"`. `pTarget` is a
keyword/target-resolved responder that is validated as a creature but not
guaranteed to be an `AiAgent`; wrapping `LuaAiAgent(pTarget)` would assert the
same way.

**Modifications**:
- Precede the wrap with `SceneObject(pTarget):isAiAgent()` (safe) and only
  call `LuaAiAgent(pTarget):healCreatureTarget(pPlayer)` when true; otherwise
  skip. Keep the enclosing `safeCall`.

## Technical Considerations

- **Pattern Usage**: The C++ method mirrors the adjacent `LuaCreatureObject::isAiAgent`
  exactly (same registration slot, same push shape). The Lua guard mirrors the
  already-correct `ai_registry.lua:110` (`SceneObject(...):isAiAgent()`) and
  the entertainer helper's player-first defensive style.
- **Locking & References**: None introduced. `isSimPlayerBot`/`asAiAgent`/
  `getSimPlayerBot` are pure reads on the already-wrapped object; `isAiAgent`
  (the analog) takes no `Locker`, so neither does this. No `Reference`/
  `ManagedReference` lifetime changes.
- **IDL Impact**: None. `asAiAgent()` and `getSimPlayerBot()` are existing
  generated/native members; no `.idl` edit, no `src/autogen/` regeneration.
- **C++ vs Lua Placement**: The safe predicate belongs in the C++ Lua binding
  (structural — it removes an entire crash class); the adoption is Lua config/
  behavior. Matches the project's split.
- **Gating & Simulation-Only**: No gate — this is a crash/regression fix that
  restores prior correct behavior, not new AI behavior. No simulation-only
  boundary is crossed (no real resource/inventory/credit/market/persistence
  mutation added). Real-player buff charging/med-buff application is unchanged.
- **Dashboard Visibility**: No dashboard section needed — this is a stability
  fix with no new SimPlayer/economy state. (Optional, not in scope: a debug
  counter of rejected non-agent buff speakers.)
- **Live Verification Plan**:
  1. Owner restarts after a clean incremental build (restart is owner's call;
     required to clear the crashed GDB state and reload Lua).
  2. In-game: a **real player** walks to a Doctor Buffer (e.g. Coronet med
     center) and says "need a buff" → NPC quotes/negotiates/buffs with **no
     crash** (previously immediate SIGABRT). Confirm the same for a Musician
     and a Dancer buffer.
  3. Regression check: a SimPlayer/PvE **bot** buff trip still completes — the
     bot path (`botBuffRequest` → `handleChat` with an `AiAgent` speaker) must
     still see `isSimPlayerBot == true`. Verify via the existing PvE hunter
     buff behavior on the dashboard / logs (`realBuffs` activity) or by
     observing a bot getting buffed.
  4. Server stays up (no SIGABRT in `gdb.log`) across repeated player chat.
- **Edge Cases**:
  - Real player speaks to doctor → `isCreatureObject` true, `asAiAgent()` null
    → `isSimPlayerBot` false → normal negotiation path (the fix).
  - Non-creature object somehow routed as speaker → `isCreatureObject` false →
    helper returns false without wrapping `CreatureObject()` either.
  - Genuine sim bot (AiAgent) → `asAiAgent()` non-null →
    `getSimPlayerBot()` honored → unchanged bot flow.
  - Release build (no `DYNAMIC_CAST_LUAOBJECTS`) → the C++ path avoids the
    previously-UB mis-cast entirely.

## Type Definitions

None. One new C++ method (`LuaCreatureObject::isSimPlayerBot`) and one new
Lua-callable name (`CreatureObject(...):isSimPlayerBot()`); no new structs,
fields, or IDL types.

## Performance & Cost Impact

Negligible. `isSimPlayerBot` is an O(1) pointer cast + boolean read, only on
spatial-chat-to-buffer events (rare, human-driven). No per-tick or per-NPC
loop cost added.

## Backward Compatibility

Fully backward compatible. `AiAgent(pObj):isSimPlayerBot()` continues to exist
for genuine agents; the new `CreatureObject(...):isSimPlayerBot()` is additive.
Bot buff flows are behavior-identical; only the crashing player path changes
(now negotiates instead of aborting). No persistence/schema change.

## Test Impact

- No existing GoogleTest currently covers the custom buffer screenplays or the
  Lua↔C++ creature bindings for this predicate; none are broken by the change.
- New logic worth an optional unit test: `LuaCreatureObject::isSimPlayerBot`
  returning false for a player/non-agent and true for a sim-bot agent (mirrors
  existing `LuaCreatureObject`/`SceneObject` Lua-binding test scaffolding, if
  the TRIP-2 gate wants coverage).
- Primary acceptance is live, per project norm: player-speaks-to-buffer no
  longer crashes, and a bot buff trip still succeeds (the two verification
  scenarios above). A `/TRIP-verify` run is the natural gate given a live
  crash is involved.
