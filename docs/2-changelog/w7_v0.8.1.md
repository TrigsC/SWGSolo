## Changes

### The finding that defined the release

F_0.8.0 shipped the traversal state machine. F_0.8.1 started by asking how to make
every bot type use it, and the answer was uncomfortable: **`enterStructure()` had
exactly one caller in the entire codebase — the test harness.** No production bot
type used the machinery at all. Miners, hunters and PvP bots all reached buildings
through `moveTo`/`moveToInterior`, neither of which starts a traversal. The
foundation was exercised only by its own harness.

Zero-clip was never in that gap — it lives in the base class and already covered
every path every bot walks. Cell entry was the gap.

### Migration, one bot type per stage

- **Stage 1 — hunters** (`SimHunterController.cpp:516`): the buff-provider approach.
- **Stage 2 — PvP collector approaches** (`SimPvPController.cpp:1312`, `:1536`).
- **Stage 3 — PvP starport waypoints** (`:1296`, `:1377`, `:2105`) — where the volume
  is: on a hollow-collector starport (64 of 70 measured approaches) the interior
  waypoint is the *only* building entry in the journey.

Each migration is cell-guarded. The stage 2 sites additionally guard on the feature
gate, because `enterStructure`'s null-cell fallthrough calls `moveToInterior` while
the legacy call there was `moveTo`; without that guard, gate-off behaviour would have
changed. Stage 3's sites need only the cell guard — their legacy call already *was*
`moveToInterior`. A starport hollow resolves to a null cell and stays an outdoor
approach, per the standing constraint that a hollow is frequently the destination.

Result: distinct agents emitting `ST_PHASE` went **0 → 17 → 84**, and the released
verification run measured **61 production agents** on ordered phase traces.

### Structural fixes found along the way

- **`acceptFoundPath` is now a non-virtual template method.** `SimPvPController`
  overrode it wholesale and never chained, silently opting PvP leaders out of the
  P.6.1b stale-path defense and D2b far-side egress. A controller that tries to skip
  the invariants now gets a compile error.
- **Both PvP collector approaches passed `collectorWorld` as the cell-*local*
  argument** — the F_0.4.7 world-coord-as-cell-local class, masked only because hollow
  collectors make the two identical. Verified load-bearing in the live trace: local
  `(-10, 10, 7.98)` against world `(-4796.4, 4252.89, 13.93)`.
- **Ordering hazard**: `moveTo` clears an active traversal, and
  `clearStructureTraversalState` resets `cellEgressSuppressed` — silently wiping a
  suppression set on the following line once stage 3 left a traversal active.

### Two defects the migration exposed

- **Indoor z-sanity fired on correct movement.** Its reference is
  `CollisionManager::getWorldFloorCollision` — the *world/terrain* floor, with no
  cell-aware overload. A PvP bot walking a Theed starport ramp logged 15 consecutive
  violations at an identical 2.40m step with dz 0.184m (a constant ~4.4° slope) while
  `floor` stayed pinned at terrain height 6.0 and the bot climbed to 13.67. A correct
  walk. Now skipped while cell-parented; the indoor gap is recorded in
  `COVERAGE-DEBT.md` with a `getWorldFloorCollisions` escape plan.
- **The harness anomaly assertions were global.** They compared process-wide counters
  against a per-step baseline, so *any* bot in the world could fail a harness scenario.
  Safe only by accident before this release, since no production bot ran traversal.
  Now per-agent — and there were **two** such sites, not one: the per-scenario check
  was missed in stage 2 and caught in stage 3 when
  `mos_eisley_starport_deep_foyer4` failed with **both its steps passing**.

### Review fixes (Codex, 5 rounds)

- **Anomaly carry across a scripted death.** Scenario 22 replaces its harness body
  mid-scenario; the fresh controller's tallies start at zero, so a pre-death anomaly
  passed silently. Each harness slot now carries its destroyed bodies' tallies, folded
  at `destroyStructureTraversalTestBot` — the single choke point all five destroy paths
  pass through.
- **That fix was itself racy**, twice. Counters are now `std::atomic<uint64>` with
  relaxed ordering (the oracle reads the live controller off-thread on the ordinary
  path too, not only at teardown), and the final fold happens under the existing agent
  lock.
- **A production robustness bug came out of a test-oracle finding.** `checkArrival`
  guarded on `agent->getZone()` *before* taking the agent lock and never rechecked
  after. A task passing that guard could block on the lock and resume after teardown —
  refilling patrol points and calling `findNextPosition` on a **world-destroyed
  agent**. Not test-only: recovery despawn calls `destroyObjectFromWorld` under the
  same lock. Now rechecked immediately after acquisition.

### Config (ungated, deliberate)

Hunter-facing `desiredReserve` raised to 500k on the four hide/bone/meat demand
families, in its own commit (`7b59646fe3`). Hunt dispatch is gated on demand pressure,
and the families saturating is the documented P.8.7 mode where the roster idles at
`IDLE_HOME`. **This is a live behaviour change and is NOT gated**; it is isolated so
the traversal commits stay inert. The real long-term fix is a consumption side, not a
higher reserve.

### Not claimed

**`exitStructure` still has only the harness as a caller.** Bots enter through the
state machine and leave through the legacy bounded ladder, which is measurably
healthy. Migrating the egress was implemented, measured and reverted (29 `ST_FAIL`,
all on exit generations, `still_inside/attempt_cap` 29/29). A second timeboxed attempt
fixed the diagnosed phase-selection defect — `entry_path_found` went 13 → 0 — and
still failed, proving that flip was a symptom. The real blocker is now localized: the
egress candidate generator emits a **constant** cell-local coordinate
`(52.2111, 10.3264, 0.593417)`, identical across eight cells in different buildings
across two runs. Tracked in `docs/1-plans/F_0.8.2_traversal-egress-adoption.plan.md`.

Miners are deliberately not migrated — owner-confirmed they have no reason to enter
cells, since station travel teleports them to an outdoor arrival by design.
