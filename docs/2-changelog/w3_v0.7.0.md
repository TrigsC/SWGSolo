## Changes

### Feature — controller-driven PvP combat engagement (P.6.6, F_0.7.0)

Before F_0.7.0, PvP squad combat was driven emergently by the stock behavior
tree while the C++ controller drove only travel/movement. That produced the
symptoms the owner observed live: bots converged "strangely," clipped through
starports, stacked ("10 jedi in 2 m"), and — under fire without line of sight —
approached-and-never-shot into a wall until they died passively.

F_0.7.0 gives `SimPvpBotController` a full, opt-in combat pipeline:

1. **Scan + acquire** — a ~100 m detection radius; a shared target-eligibility
   helper (`isEligiblePvpCombatTarget`) accepts only real players or enabled
   sim-bots, so ordinary wild/world NPCs are never dragged into the controller
   lane (they keep stock self-defense). Both the scan path and defender adoption
   funnel through the single `acquireControllerCombatTarget`.
2. **Cell-aware approach** — `driveCombatMovement` → `approachTarget` requests a
   portal-graph path when the target is in a cell (no straight-line clipping
   through starport walls); outdoor pursuit uses the hybrid overland path.
3. **Engage + hold** — within weapon range the controller calls
   `CombatManager::startCombat` and holds a weapon-stock band; stock combat
   enforces "no damage without LOS", so the controller **holds regardless of LOS**
   rather than clearing combat to chase (Fix B — LOS is now telemetry-only,
   counting false→true obstruction transitions). No-stacking hold + in-cell
   engagement are allowed.
4. **Movement arbitration** — while engaged the controller swaps in a
   `simPvpCombat` no-op-MOVE AI map (`setCustomAiMap` + `setAITemplate`, with
   `formationOffset` preserved/restored) so the stock tree's MOVE socket cannot
   double-drive movement; teardown restores the base map.
5. **Traversal wins (P.6.6a)** — `isInteriorTraversalActive()` suppresses combat
   while a member is mid-starport-run, so a member finishes its traversal leg
   before engaging (no combat/traversal deadlock).

### Feature — squad aggro-sharing / combat contagion (P.6.6b, F_0.7.1)

When one squad member engages, the **whole squad** should converge and fight, not
sit back and heal while a squadmate dies. F_0.7.1 adds a thin, default-off
squad-level broadcast on top of the P.6.6 lane:

1. **Shared aggro set** — each `SimPvpSquad` holds a small, capped, TTL-refreshed
   set of enemy OIDs its members are engaged with (`recordPvpSquadCombatTarget`,
   published on acquire and kept alive by a throttled re-publish in
   `driveCombatMovement`), guarded by `pvpSquadMutex`. OIDs are resolved to
   `ManagedReference` and any agent lock is taken **outside** the mutex.
2. **Converge when idle** — an idle controller with no target queries
   `getPvpSquadSharedCombatTargets`, iterates all live candidates, and acquires the
   first that passes faction/zone/cell/radius/eligibility, marking
   `combatIsConvergenceTarget`.
3. **Convergence-specific bounds** — a shared target is a *known* teammate contact,
   not a fresh scan hit, so convergence uses a larger radius
   (`squadAggroConvergeRadiusMeters` = 300) and its own longer timeout
   (`squadAggroConvergeTimeoutMillis` = 60 s) instead of the 100 m / 15 s engage
   bounds — otherwise a distant squadmate would abandon a reachable fight.
4. **Self-limiting** — dead/departed shared targets are pruned (TTL + liveness) and
   released (`targetUnavailable`); a `failedSharedTargetOid` ignore window stops a
   member thrashing a contact it just proved it can't reach.

### Dashboard

New `pvpActivity.combatEngagement` section: `controllerDrivenEngage`,
`squadAggroSharing`, `convergencesTotal`, `approachesActive`, `engagementsInRange`,
`losBlockedAttacks`, `inCellEngagements`, per-squad `activeTargets`/`sharedTargets`,
and a `starportTraversal` sub-section. Rendered under `#/warfront` in `app.js`.

### Gating / safety

All new behavior is **default-off** (`pvpConfig.combat.controllerDrivenEngage`,
`squadAggroSharing`, `logCombatMovement` all `false`) and simulation-only (no
inventory/credit/market/persistence mutation; PvP kills are the existing bot-vs-bot
sim). Enable at runtime; reversible at runtime.
