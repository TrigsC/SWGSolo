## Changes

P.6.5b makes PvP squad starport departures player-mimetic (plan:
`docs/1-plans/F_0.2.0_p65b-boarding-realism.plan.md`; design doc §13):

- **Departure-port realism**: route planning moved to loiter-end
  (`onPvpSquadDepartureIntent`, consumed by a centralized `enterToShuttle`
  covering all three `PVP_TO_SHUTTLE` entries), so interplanetary departures
  run to the actual starport's ticket collector — interior at Theed via new
  cell-aware path support in `SimPlayerController` (outdoor paths, i.e. all
  miners, are byte-identical no-ops). Collector positions cached per port
  (`resolvePvpBoardingPoint`, both world and cell-local forms, Kaadara
  z-sanity check, starport-pad fallback).
- **Tactical arrival** (`avoidHotArrival`): non-convergence routes to a "hot"
  city (enemy squad stationed, or own faction's unexpired contact) land one
  same-planet city out and append a shuttle leg in; convergence responses go
  direct (owner decision).
- **`boardOnActualShuttle`** knob formalizes the real-ship wait (escape hatch).
- **Engine fix (review finding)**: `AiAgentImplementation::findNextPosition`'s
  multi-node loop mixed cell-local and world coordinates — latent while all
  patrol points were outdoor; would have stalled interior runs. Distances and
  interpolation now computed in the next node's coordinate space.
- Intra-planet legs now arrive at the destination's shuttle pad (was starport
  pad). Dashboard: `routedTravel` counters/config/cache + `pageWarfront`
  ROUTED TRAVEL panel. Lua: `useCollectorBoarding`, `avoidHotArrival`,
  `boardOnActualShuttle`, resolver knobs (C++ defaults conservative).

Simulation-only, runtime-flippable. Live verification checklist: design doc
§13.3, pending owner restart (verify the P.6.5a §12 orphan fixes first).
