## Changes

### Crash fixed

Speaking a buff request to the Smart Doctor Buffer NPC as a **real player**
hard-crashed the zone process (SIGABRT). The P.8.6 buffer→PvE-bot buff work
(F_0.4.6) added a sim-bot gate that wrapped the *speaker* as `AiAgent(pObj)`;
when the speaker is a real player (not an `AiAgent`), that wrap tripped the
debug-build assertion `!_getRealSceneObject() || realObject != nullptr` in
`LuaAiAgent::_setObject` and called `abort()`. The surrounding `pcall`/`safeCall`
wrappers could not catch it because `abort()` is a process signal, not a Lua
error.

### Fix — safe predicate + guarded wraps

- **C++ (defense-in-depth):** `LuaCreatureObject` now exposes `isSimPlayerBot()`,
  resolving the agent through the native safe cast `CreatureObject::asAiAgent()`
  (returns `nullptr` for non-agents — no `dynamic_cast`, no assertion) and
  returning `getSimPlayerBot()`, else `false`. Lua can now ask any creature
  whether it is a sim bot without ever wrapping `AiAgent()`. (`LuaCreatureObject.h`,
  `LuaCreatureObject.cpp`.)
- **Lua (adopt the safe path):** the three custom buffer scripts replace the
  unguarded `AiAgent(pObj):isSimPlayerBot()` with an `isCreatureObject()`-guarded
  `CreatureObject(pObj):isSimPlayerBot()`:
  - `smartDoctorBuffer.lua` — the actual crash site.
  - `smart_entertainer_helper.lua` — latent sibling (musician/dancer buffers).
  - `aiGlobalChatHandler.lua` — the legacy `LuaAiAgent(pTarget):healCreatureTarget`
    wrap is now guarded by `SceneObject(pTarget):isAiAgent()`.

Behavior for genuine bots is unchanged (an `AiAgent` still reads the same
`getSimPlayerBot()` flag); real players and non-creatures now safely resolve to
`false` and negotiate normally instead of aborting the server. No new gate, no
IDL/persistence change, simulation-only posture untouched.

### Verification

Owner-attested live verification: after an owner-approved restart, a real player
spoke a buff request to the doctor — the buff applied with **no SIGABRT**, no
`gdb.log` was written, `core3` stayed alive, and the REST dashboard stayed live.
PASS receipt: `.claude/verification/latest.json` (4/4 assertions).

### Known follow-up (not part of this release)

A separate **pre-existing** bot→doctor buff-trip anomaly was observed while
verifying (PvE hunters take the synthetic-fallback buff instead of completing
the real doctor buff; one bot seen stuck at a doctor). It is **not** a regression
of this change — bot detection reads the identical `getSimPlayerBot()` flag
before and after — and is deferred to its own diagnosis.
