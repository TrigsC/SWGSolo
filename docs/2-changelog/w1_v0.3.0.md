## Changes

P.6.5d fixes the two owner-reported live gaps after P.6.5b (plan:
`docs/1-plans/F_0.3.0_p65d-city-loop-realism.plan.md`; design doc §14):

- **City-loop realism**: every city now has three distinct live-data
  locations — starport (cross-planet), city shuttleport (new `shuttlePoint`
  exact travel-point names for all 10 cities; intra-planet legs depart AND
  arrive there), and hangout. Hangouts default to the nearest validated
  cantina exterior (navmesh-membership + collision-footprint checks;
  `findPath` supplies only the walk-in point — never validates); Theed keeps
  its hand-placed spot (`hangoutManual`). Squads visibly run across town at
  every city instead of standing at the starport.
- **Break-off cohesion (anti-gank)**: 2 squad deaths within 120s during the
  city loop → RETREAT callout (bypasses both announce cooldowns), squad
  aborts via the convergence-interrupt choreography, avoids that city for
  600s, and routes elsewhere; a different squad converges on the contact.
  Single-shot latch survives the leader being the threshold death — leader
  promotion speaks the RETREAT and drives the break-off departure instead of
  re-entering the killzone. All Lua-gated (`pvpConfig.cohesion`), C++
  defaults off.
- **Review-driven lifecycle hardening**: the city-location resolver refuses
  to cache while the server is loading OR before the city's navmeshes are
  built (shuttle-pad mesh probe — mesh jobs start only after loading
  finishes); the dashboard is a peek-only cache consumer; a retryable
  maintenance warmup completes the rows ~30s after boot.
- Dashboard: `routedTravel.cityLocations` per-city rows (pad resolution,
  hangout source manual|cantina|fallback, pathNodes), `breakOffsTotal`,
  cohesion config echo, per-squad cohesion fields; SPA Break-offs metric +
  city-hangouts summary.

Simulation-only, runtime-flippable. Live verification checklist: design doc
§14.2, pending owner restart (includes a staged-gank test).
