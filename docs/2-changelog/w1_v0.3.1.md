## Changes

P.6.5e (plan: `docs/1-plans/F_0.3.1_p65e-stalemate-break.plan.md`; design doc
§15). Owner-observed live: opposing sim bots frozen inside each other at
Theed Spaceport's interior collector for 10-20 minutes (combat freezes sim
movement; cell-portal LOS blocks every attack; phantom guard can't clear a
live 0m defender; only the 600s+ backstop or a reform ends it).

- **Stalemate break** (the P.6.2b-flagged follow-up, shipped): per-tick
  combat-progress tracking (current HEALTH/ACTION/MIND on self + defender;
  wounds/regen excluded) in `SimPvpBotController::onTick` — covers leaders
  and members. 45s without any HAM decrease → `clearCombatState`, walk away,
  and ignore that one enemy for a 20s grace (own target scan only; the
  engine defender path stays unfiltered so a landed hit resumes real
  combat). Zero-preserving config parse so a Lua `0` genuinely disables at
  runtime. Stalemate state resets on relocation; member teleports get a
  scoped reset (full relocation would orphan the follower tick chain).
- **Collector wait jitter**: deterministic golden-angle offset per squad
  (~3m) on collector departure targets — cell-local-only for Theed's
  interior — so two squads never occupy one exact point.
- Dashboard: `stalemateBreaksTotal` + config echoes; SPA metric. Lua:
  `cohesion.stalemateBreakSeconds=45`, `cohesion.stalemateGraceSeconds=20`,
  `travel.collectorJitterMeters=3` (C++ defaults off).

Expected live effect (§15.2): statue pairs break in ~45s; the
`clearCombat+forceAdvance` hard-stuck volume (26/12.3h baseline) collapses;
fights still resolve with deaths.
