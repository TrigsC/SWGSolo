## Changes

### Training now changes how a bot fights

F_0.9.5 gave a PlayerBot real skill boxes and F_0.9.6 made it earn the XP for
them, but the body still swung a plain auto-attack: `sim_playerbot_novice` ships
`primaryAttacks = {}` and `setupAttackMaps` reads only the mobile template. This
chunk derives each bot's attack list from `simbot_skills` — the same `commands`
column a real player's boxes grant — and installs it on the locked `AiAgent` as a
transient overlay beside the existing SKILLBOX skill-mod overlay. Nothing new
persists: the list is re-derived at every spawn, training and gate change.

Only the **highest tier of each ability chain** is installed. The chain key is the
command name with trailing digits stripped, so `unarmedhit1` and `unarmedhit2`
both give way to `unarmedhit3`, while `unarmedheadhit1` stays its own chain. A
brawler master derives 23 abilities; adding Teras Kasi master takes it to 29 with
four multi-step chains collapsed.

### The instrument found the bug before the reviewer could

The live probe — the first thing this verification did — showed almost every
ability being thrown away as `unknown_command`. `skills.iff` spells commands in
camelCase (`unarmedHit1`), the `ObjectController` registry is keyed lower case,
and `getQueueCommand` hashes the exact string: only names that were already
lower case (`intimidate1`, `taunt`, `warcry1`, `aim`) survived. One
`toLowerCase()` before exclusion, lookup and installation turned 3 derived
abilities into 23. No unit test would have caught it; nothing in the code looks
wrong at either end.

### Specials that cost what a player pays

`CombatManager::applySpecialAttackCost` returns early for every AiAgent, so stock
NPC specials are free in Health/Action/Mind. Letting bots keep that would have
been a cost advantage, so the player arithmetic is extracted into a shared
`specialAttackHamCostFromInputs` and skill-derived agents alone pay it, with the
same refusal rule. A configurable HAM reserve stops a special's **own** spend from
pushing a pool below the threshold — and only the pools it actually spends, since
the first cut refused free unarmed specials from a merely wounded bot 186 times
and left it dealing no damage at all.

### Choosing an attack, and three live failures that shaped the rule

Selection reuses the existing state-aware NPC scorer unchanged and adds two
pre-filters for skill-derived agents: the HAM reserve, and a rejection of any
special the behaviour tree's `CheckAttackIsValid` would refuse. That second filter
exists because the scorer's heuristics do not mirror `validateStateAttack` — lunge
is scored as a knockdown but carries POSTUREDOWN — so a bot re-picked the same
invalid lunge every tick and never attacked for a full 600 s budget.

A free **control** ability (non-damaging, zero cost, applying a state the target
lacks — Intimidate) is used by name *before* the special roll, then not forced
again on that target for `freeStateRetrySeconds`. The first design checked it only
on a missed roll, which meant a 100 % special policy never used Intimidate at all;
an earlier one handed the choice back to the scorer, which preferred a damaging
lunge and re-fired every tick because the unarmed weapon makes everything "free".

`taunt`, `warcry1` and `warcry2` ship excluded: a forced-special novice spent an
entire kill budget fighting bystanders those area abilities pulled in.

### Seeing what a bot is

Three read-only surfaces share one snapshot builder: a Bearer-gated
`GET /v1/aieconomy/playerbot/<id>/`, a click-a-name drawer on the dashboard's
WILDS and progression tables, and `/server playerinfo` with a SimBot targeted —
which previously fell back to showing the admin their own record. Each reports
identity, body and weapon templates in plain terms, trained boxes by profession,
next box, skill mods, active/superseded/excluded abilities and recent ability use.
Derivation is deliberately **gate-independent**: with the capability off the view
still shows what the boxes would grant and says why nothing is installed, which is
what made the probe possible before anything was enabled.

### Verification

27/27 assertions (`20260916-144849`): the probe confirmed real tier chains and
weapon costs; the parity matrix ran 63 + restart probe then 64/64 including four
new ability scenarios; a 47-minute gated grind produced 68 kills, 46 XP awards,
23 Intimidates, 139 auto-attacks against 127 specials, 1 569 attacks on an
intimidated target, zero reserve refusals and no superseded ability ever
installed; and the owner confirmed both in-game checks. Eight defects were found
by verification rather than review.

**Open item**: the first matrix attempt hit a SIGSEGV in
`AiAgentImplementation::notifyDespawn` on a harness kill-target corpse whose
`_this` weak reference pointed at freed memory. Two defensive harness fixes ship,
but the crash did not reproduce in 9 boots and ~400 kills — including 6
full-matrix and 3 stress boots with both fixes reverted — so the root cause is
unconfirmed. It is outside the ability path: the victim was a wild creature with
no skill-derived attacks. Forensics are preserved under
`bin/log/trip-verify-20260916-144849-p10h-skill-abilities.crash1-*`.
