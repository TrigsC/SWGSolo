## Changes

### Structure traversal foundation (P.9)

Entering and leaving a POB (portal object building) stops being an ad-hoc
sequence of `moveTo` calls and becomes an explicit state machine on
`SimPlayerController`:

- **Phase/generation model** — `StructureTraversalPhase`
  (`Idle → ApproachDoor → InteriorRoute → Egress → Reentry → CombatPaused →
  Resuming`) with a `traversalGeneration` that lets combat cancel a movement
  task without cancelling the traversal intent. Every transition is traced to
  `bin/log/structuretraversal.log` behind `structureTraversal.logging`.
- **Hollow escalation** — a bot stuck inside a starport's enclosed hollow (the
  walled landing pad, cell 0 but boxed in) escalates to a door rather than
  wandering. Bounded by `hollowEscalationAttemptCap`.
- **D2b far-side egress** — the dominant failure mode. From inside a starport
  the pathfinder answered "reach the west exterior door" with a valid route out
  the *nearest* portal, back into the hollow: a path that succeeds while making
  no progress, so the existing repair ladder (which only runs on path
  *failure*) never engaged. `acceptFoundPath` now rejects a route that ends
  back inside the owning building's hollow while the destination is outside it,
  and retargets to the nearest reachable non-hollow exit **cell**, which the
  pathfinder routes through the interior correctly. Matrix 11 PASS → 22 PASS.
  The predicate deliberately exempts the case where the destination is *itself*
  in the hollow — multi-hop planet transit lands a bot on the pad and it must
  not be marched out the far side.
- **D8 hollow door egress** — pad-side door resolution via `CellProperty`
  portals, an entry-side arrival guard mirroring the egress one, and an
  `InProgress` escalation outcome so an in-flight interior approach is not
  mistaken for arrival.

### Live scenario harness

A 26-scenario matrix (`structureTraversalTest` in `sim_player_manager.lua`)
spawns tagged bots and drives enter/dwell/moveTo/exit sequences with per-step
budgets, scripted combat interrupts, death/respawn, external preemption and
two-bot concurrency — including a **multi-hop transit** scenario (hollow → cell
→ hollow) that reproduces the ticket-terminal/ticket-collector round trip.

Two harness defects found by review and fixed, both of which had been
weakening the evidence rather than the product:

- Exit assertions resolved the building by walking *backwards through the
  scenario config*, so a cell-only step resolved to nothing (and failed **open**)
  while a two-building scenario asserted against the first one. The owning
  building is now captured from the **resolved** enter target and the assertion
  fails **closed**.
- The runner was not genuinely single-writer — an unlocked check-then-set on
  the arming flag, cleared at entry, let a controller callback start a second
  concurrent runner over the same scenario cursor. Ownership is now held under
  the harness mutex for the whole invocation, with a rerun latch so a contended
  zero-delay wake-up is never dropped.

### Zero-clip movement (D7) — observe, and enforce default-off

Owner requirement: bots must not clip through buildings. Phase 1 (observation)
and Phase 2 (enforcement) both ship, **both gated off**.

- A segment-clearance probe runs on the pathfinding worker thread, off the
  movement path, with explicit outcomes (`clear` / `would_block` / `skipped` /
  `truncated` / `error`) aggregated worst-evidence-first so an inconclusive
  probe can never read as clear.
- Enforcement (`zeroClip.enforce`) refuses a conclusively obstructed route and
  re-asks, bounded by `zeroClip.rejectionCap`; on exhaustion it walks the route
  rather than strand the bot, recording `zeroClip.capExhausted`. It fails
  **open** on inconclusive probes — deliberately the opposite of the harness
  assertion, because a mover that cannot see must still move.
- **The measured block rate was about half false positive.** The appearance ray
  tests the straight chord between two path nodes, which for a staircase or
  bridge deck dives through the solid mass *beneath the walkable surface*.
  `zeroClip.walkableConfirm` confirms a flagged chord against the navmesh — the
  authority on what an agent can stand on — and overruled 110 of 206 raw hits.
  Naboo bridge stairs, seawall rocks and ruined gungan walls left the blocking
  list; starport shells and solid debris stayed.

Result: clip rate of paths bots actually walked **11.3% → 3.4%**, with matrix
verdicts unchanged at 22 PASS / 4 FAIL and zero regressions.

**Not done, and not claimed**: D7 acceptance criterion §5.1
(`crossesGeometry == 0`) is **not met**. The residual is genuine clipping
through starport shells and debris; closing it needs a detour generator or
navmesh coverage of those objects. Both zero-clip gates therefore ship off.
Codex's maximum-horizontal-deviation discriminator is recorded as the
recommended successor to the length-ratio heuristic.

### Engine note

`PathFinderManager::getRecastPath`'s `float& len` out-parameter is **not a path
length** — it accumulates `x² + z²` of each point's absolute world coordinates.
`findPathFromWorldToWorld` consumes it only as a relative comparator
(`finalLengthSq`); `CollisionManager::checkMovementCollision` passes a value in
and ignores it. Anything needing a real length must measure it from the
returned points.
