## Defect found and fixed during verification

Live verification found one real defect that a warning-clean build and two APPROVED
Codex reviews had both missed.

**Named identity refs were pruned mid-flight.** Scenario 28's final
`deleteIdentity{identityRef="killBot"}` failed with `identity_not_found`.
`deleteIdentity` is an asynchronous op whose identity is re-resolved on *every* poll,
but the `DeleteIdentity` request handler removed the named ref when the request
completed — so the very poll that observed completion resolved a ref that had just been
erased. Positional `deleteIdentity{identityIndex}` never hit this because that handler
never touched `playerBotParityTestIdentityIds`, only the refs map: the new named-ref
addressing mode inherited an async lifetime the positional one never had. Fixed by
deleting the prune (refs are scenario-scoped and already cleared wholesale by the cleanup
pass) with a comment recording why it cannot live there. Codex re-reviewed and APPROVED.

Notably, the first run's scenario 28 passed every *substantive* step — spawn, kill,
oracle match, flush, reload, re-assert — and failed only on cleanup, so the feature itself
was proven before the defect was fixed.
